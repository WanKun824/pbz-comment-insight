# 影之刃零 B站评论标签体系 v2 + 训练计划

> 本文保留早期设计与训练计划，后文的时间、目标和脚本名属于历史方案。
> 当前实现为 14 个一级正交问题、8 个一级主题与 67 个二级主题；实际命令见 [README](../README.md)，
> 当前中文名称、完整对照、输出字段与迁移步骤见 [两级中文标签](两级中文标签.md)。

数据：`comments_all.csv`，9,696 条，7 个视频，2026-10-22 ~ 2026-11-02
游戏类型：**单机买断制动作游戏**（因此全套手游词表——抽卡/体力/排位/外挂/服务器经济——全部删除）

## 一、数据层必须先修的 2 个 bug

### bug-1（阻断级）：`rpid` 被科学计数法摧毁

```
rpid 样例: 3.21944E+11 / 3.21945E+11
唯一 rpid 数: 1579  ←  实际行数 9696
```

9,696 行只剩 1,579 个不同 rpid，**47.7% 的楼中楼无法关联回主楼**。
原因：写 CSV 时 rpid 被当 float 处理（或经 Excel 另存）。

修法：`_cache/*.json` 里 rpid 是字符串且有 `root`/`parent` 字段，关系完好。重新导出即可：

```python
# 导出时
df['rpid'] = df['rpid'].astype(str)
df.to_csv(path, index=False, encoding='utf-8-sig')
# 读取时
pd.read_csv(path, dtype={'rpid': str, '主楼rpid': str, 'UID': str})
```

### bug-2：`情感` 列串行污染
有 1 行 `情感 = "游行行业"`（主题值跑进了情感列）。标注工具必须做枚举校验。

### 附带问题
- `IP属地` 全部为"未知" → 该列无信息量，地域维度做不了，别在看板里留这个坑。
- `情感分数` 34–87，均值 63、标准差 11，**区分度极低**；且与三档标签不一致（70% 落"中性"）。v2 弃用连续分。

## 二、现有 50 条标注的诊断

28 个标签 / 50 条 = 平均每标签 1.8 条样本。四类硬伤：

### 1. 同义与错别字重复（8 组，必须合并）

| 旧标签组 | 问题 |
|---|---|
| `游戏行业评价`(6) / `游行行业`(3) | 错别字，同一个类被拆成两个，还污染了情感列 |
| `游戏适配`(1) / `游戏适配问题`(1) | 「问题」是 has_issue 维度，不是新主题 |
| `玩家互动`(1) / `玩家间互动`(1) | 完全同义 |
| `游戏玩法`(1) / `玩法评价`(1) | 「评价」是 speech_act 维度 |
| `剧情评价`(2) / `剧情解析`(1) | 同主题，差异在 speech_act |
| `开发者互动`(3) / `制作人互动`(1) / `调侃制作组`(2) | 三个一回事，差异在 speech_act=joke |
| `游戏手感`(3) / `游戏玩法`(1) | 边界未定义，标注者会随机二选一 |
| `游戏热梗`(2) / `同类游戏欢乐互动`(3) | 都是梗，后者多了「提及其他游戏」这个独立维度 |

### 2. 维度混淆（最严重，4+ 个标签根本不是主题）

把**主题**、**言语行为**、**评价对象**、**有效性**、**意向**五个正交维度全塞进了一列：

- `垃圾信息与主题无关` → 这是**有效性**维度
- `期待游戏发布` → 这是**购买意向**维度（其内容主题可能是定价/剧情/任何东西）
- `游戏热梗` / `同类游戏欢乐互动` → 这是**言语行为**(玩梗)维度
- `游戏博主互动` / `玩家社群` / `玩家互动` → 这是**评价对象**维度
- `游戏对比` → 这是**对比关系**维度；对比的内容本身仍是手感/画面/销量

后果：同一条评论可以合法地落进 3–4 个旧标签，标注者之间不可能一致，κ 必然低。

### 3. 粒度不一致
`游戏行业评价`（产业宏观）和 `游戏手感`（单一体感）同级，互斥性不成立——
「国单的手感终于追上卡普空了」该标哪个？

### 4. 工程上直接不可用
28 个标签已超 Laya 的 `choice` 可用区间（>20 选项断崖，Banking77 仅 0.425），
且这个体系必然继续膨胀到 50+。

## 三、v2 优化后的体系

**核心手术：一列拆成 14 个正交问题，主题做两级。**
机器可读版本：`taxonomy/labels_v2.json`（由 `pbz.schema` 统一渲染）

### Pass 1 —— 14 个问题，一次前向全出

| # | 问题 | 类型 | 选项数 | 作用 |

| 2 | `sentiment` | choice | 5 | very_neg → very_pos（替换旧三档+连续分） |
| 3 | `is_mixed` | choice | 2 | 是否褒贬并存（旧体系把这类全压成"中性"） |
| 4 | `target` | choice | 7 | game / dev / publisher / creator / other_player / other_game / none |
| 5 | `speech_act` | choice | 7 | review / report / question / suggest / share / joke / argue |
| 6 | `has_issue` | choice | 2 | 能否立案跟进 |
| 7 | `purchase_intent` | choice | 2 | 购买/开玩意向 |
| 8 | `churn_signal` | choice | 2 | 不买/劝退/退款 |
| 9 | `is_spoiler` | choice | 2 | 剧情泄露 |
| 10 | `is_toxic` | choice | 2 | 辱骂引战 |
| 11 | `is_sarcasm` | choice | 2 | 反讽阴阳（**最难，必须靠微调**） |
| 12 | `is_actionable` | choice | 2 | 含可执行建议 |

二级标签按所属一级主题维护中文映射。当前模型内部路由标识保持兼容，预测、概率字典、报告和看板输出中文。

## 四、这个体系为什么必须这么设计（数据证据）

我对 9,696 条跑了 21 组关键词探针，结果直接决定了几个设计：

| 探针 | 命中占比 | 对体系的含义 |
|---|---:|---|
| 社区_梗与玩笑 | **15.0%** | 梗是第一大类——必须给 `banter` 独立档位，否则污染所有主题 |
| 战斗_难度 | 10.8% | 战斗主题必须拆出战斗难度和首领战斗 |
| 战斗_手感 | 9.5% | 手感是核心争议点（与卡普空对比），要细分战斗手感与拼刀精防 |
| 玩家_自述体验 | 9.2% | 「玩家自述」必须是一级类，原体系只有 1 条「玩家故事」 |
| 剧情_叙事 | 7.6% | — |
| 关卡_地图 | 7.1% | — |
| 对比_黑神话 | **7.0%** | 对比必须是独立维度 + 独立 L2 |
| 对比_鬼武者/魂 | 6.3% | 同上 |
| UP主_视频 | 5.9% | 「视频与UP主」必须是一级类 |
| 媒体_评分 | 5.8% | — |
| 社区_舆论节奏 | **5.3%** | 「节奏/对立/阴阳」是本话题特征，需 is_sarcasm + discourse |
| 玩家_购买决策 | 5.2% | 需 purchase_intent / churn_signal 两个独立二分 |
| 性能_优化帧数 | 4.8% | — |
| 行业_国产3A | 4.6% | — |
| 适配_外设平台 | 3.4% | 手柄键位是真实痛点（已有标注里出现 2 次） |
| 玩家_周边收藏 | 0.5% | **稀有类，训练集必须过采样** |
| 噪音_无关 | 0.2% | spam 极少，但召回要求高 |

两个结构性结论：

1. **35.8% 的评论命中 0 个探针** → 绝大多数是楼中楼碎片（"又是魂"、"捉猫"、"收钱了"）。
   不设 `valid` 闸门，这 1/3 的数据会被强行分到某个主题，把所有指标拖垮。
   同时：**长评论（≥80字，占 9.8%）里只有 3.9% 命中 0 探针** → 高价值信息高度集中在长评。

2. **14.3% 的评论命中 ≥3 个探针** → 真·多主题。
   `topic_l1` 单选只能拿主主题；多主题由 `mentions_other_game`、`has_issue` 等二分维度补齐。
   需要完整多标签时，再加一组「是否提及 X」的两选项 choice（**不要用 noul**）。

3. **47.7% 是楼中楼、15% 带"回复 @"** → state 必须拼 `视频标题 + 父评论 + 正文`，
   否则这半数数据语义不完整。这也是为什么 bug-1 是阻断级的。

## 五、Laya 工程约束与规避（全部来自官方实测，不是猜测）

| 约束 | 规避 |
|---|---|
| 中文 `noul` 会退化成常数 true（官方 zh 基准 0.667→0.458，`wants_stop` 对 18 条全答 true） | 所有二分维度用**两选项 choice**，键用 `A`/`B` |
| `score` 是最弱原语（SST-5 仅 0.372）+ multilingual 在 score 上很少选第一项（#131） | `sentiment` 用 5 档 **choice** |
| 选项位置改答案（同文本 5 选项 logit 中心 `[+1.68,+1.47,+0.11,-1.35,-1.91]`） | `option_order` k 次轮转平均，k 个轮转放**同一次前向**（官方：不一致率 16.3%→6.1%） |
| >20 选项断崖（Banking77 0.425） | 两级：L1 8 选 1 → L2 ≤10 选 1 |
| 否定/反讽零样本必崩（#377：4 个否定请求全错） | `is_sarcasm` 必须微调，且是人工标注重点 |
| 中文必须走 multilingual | `Router` 会自动路由；长评 `max_len=8192` |
| 出厂温度未拟合（multilingual 根本没有） | 必须 `fit_abstention_thresholds` 拟合后再用置信度门控 |
| 多选项时 head 会超 `head_max_len` | 设 `head_max_len=384, max_len=768`（L2 有 10 选项且描述长） |

### 推理成本估算
Pass1 共 14 问一次前向（T4：10 问 158ms → 14 问约 200ms），Pass2 再一次。
批处理后（`batch_size=64, sort_by_length=True`，消费级 GPU ~1ms/决策）：
9,696 条 × ~16 决策 ≈ **15.5 万决策 ≈ 3 分钟全量跑完**，成本 0，数据不出本机。

## 六、训练计划

### 阶段 0：数据工程（1 天）

- [ ] 从 `_cache/*.json` 重新导出 CSV，`rpid`/`主楼rpid`/`UID` 全部 `str`
- [ ] 修 `情感` 列串行；给标注工具加枚举校验
- [ ] 构造 `state`：`{"video": 标题, "parent": 父评论, "comment": 正文}`，楼中楼靠 `root`/`parent` 还原
- [ ] 清洗：去 `回复 @xxx :` 前缀（保留到 parent）、统一表情 `[xxx]`、去重（重复文本 1.87%）
- [ ] 建分层键：视频 × 层级 × 长度分桶(≤10/11-25/26-45/46-79/≥80) × 点赞分桶(0/1-7/8+)
- **产出**：`comments_clean.parquet` + `state` 字段

### 阶段 1：Golden Set 与标注规范（2–3 天，**最关键**）

- [ ] 抽 **600 条**：
  - 300 条**分层随机**（反映真实分布，用于算真实指标）
  - 300 条**探针过采样**（周边 0.5%、spam 0.2%、BUG、反讽、混合评价各保 20–30 条，用于训练稀有类）
- [ ] 写标注规范：每个标签给 **3 正例 + 2 反例 + 1 边界 case**
  重点定义边界：手感 vs 招式、剧情 vs 世界观、banter vs substantive、批评 vs toxic、混合 vs 中立
- [ ] **双人独立标注同 100 条** → 算每维度 Cohen's κ
  - κ ≥ 0.75：定稿
  - 0.6 ≤ κ < 0.75：改 criteria 描述后重标该维度
  - κ < 0.6：**合并或删除该标签**（这一步会自然淘汰掉剩余的伪区分）
- [ ] 400 条做 train/dev，200 条冻结为 **test，全程不碰**
- **产出**：`golden_600.jsonl` + `标注规范_v2.md` + κ 报告

### 阶段 2：零样本基线（0.5 天）

- [ ] `laya-multilingual` 跑 600 条，记录每维度 accuracy / macro-F1 / ECE / 混淆矩阵
- [ ] A/B：带 `option_order` 轮转 vs 不带 → 量化位置偏置实际损失
- [ ] A/B：`state` 带 parent+title vs 只有正文 → 量化上下文收益
- [ ] 同时跑一个 **baseline 对照组**：微调过的中文 RoBERTa 只做 sentiment + topic_l1
- **预期**（基于官方中文基准 6 选 1 = 0.72）：
  `valid` 0.75–0.85 / `sentiment` 0.60–0.70 / `topic_l1` 0.50–0.65 / `topic_l2` 0.35–0.50 / `is_sarcasm` ≈ 随机
- **决策点**：若 topic_l1 < 0.5，说明 criteria 描述有问题，先改描述再往下走

### 阶段 3：弱监督扩量（2–3 天）

- [ ] 用阶段 1 的规范写 LLM 标注 prompt（规范原文进 system prompt，含边界 case）
- [ ] 先让 LLM 标 golden set 的 400 条训练部分 → 算 LLM vs 人工 agreement
  - 维度 agreement < 0.80 → 改 prompt 重跑，不达标不扩量
- [ ] LLM 标 **10,000–15,000 条**（全量 9,696 + 补抓其他影之刃零视频评论）
  - 分层采样，稀有类定向补齐到每类 ≥ 150 条
  - 让 LLM 同时输出置信度，低置信 → 人工复核队列
- [ ] 转 Laya 训练格式：`{"state": ..., "questions": {...}, "answers": {...}}`
- **产出**：`train.jsonl`（~12k 条 × 16 问 ≈ 19 万决策）+ `dev.jsonl`

### 阶段 4：微调（1 天，Kaggle 免费 2×T4）

- [ ] 基座：`convaiinnovations/laya-multilingual`
- [ ] 用官方 notebook：`laya_finetune_typed_decisions_2xT4_kaggle.ipynb`
- [ ] **`TrainConfig(option_layout="parallel")`** —— 彻底消除位置偏置
  官方实测：顺序布局换序后 91.7% 一致，parallel 布局 **100% 一致**，准确率持平（0.764 vs 0.779）
  代价：需 transformers≥5、只能 eager 后端（ONNX/TileLang 不可用）
- [ ] 4 epochs，~19 万决策 ≈ 4–6 小时
- [ ] 拟合温度：**per (question_type × option_count)**，并清掉继承来的 `temperature_by_options`
  （否则旧桶值会静默覆盖新拟合，官方已踩过）
- [ ] 对照实验（各跑一遍，二选一上线）：
  - A: 单 checkpoint 全 16 问
  - B: 拆两个 checkpoint（Pass1 / Pass2），各自更专
- **产出**：`laya-pbz-comments-v1` 权重 + `rl_agent_config.json`

### 阶段 5：评测与置信度门控（1 天）

- [ ] 在**冻结的 200 条 test** 上出完整报告：每维度 accuracy / macro-F1 / per-class P/R / ECE
- [ ] `laya.calibrate.fit_abstention_thresholds` 按桶拟合 `min_confidence`
  （注意：有 `binning_map` 时必须传，否则门槛在模型看不到的尺度上——官方实测 9.8% 错误率会变成 25.6%）
- [ ] 画**覆盖率–准确率曲线**，定自动化比例
- **验收线**（低于则回阶段 1 改标签定义，不是加数据）：

| 维度 | 目标 accuracy | 目标 ECE |
|---|---:|---:|
| `valid` | ≥ 0.90 | ≤ 0.10 |
| `sentiment`(5档) | ≥ 0.78 | ≤ 0.12 |
| `topic_l1`(8类) | ≥ 0.80 | ≤ 0.12 |
| `topic_l2`(≤10类) | ≥ 0.70 | ≤ 0.15 |
| 二分维度 | ≥ 0.85 | ≤ 0.10 |
| `is_sarcasm` | ≥ 0.75 | ≤ 0.15 |
| macro-F1（主题类，防多数类作弊） | ≥ 0.65 | — |

> 必须看 macro-F1：社区舆论与玩家自述占比较高，只看 accuracy 会被多数类骗。

### 阶段 6：上线与闭环（持续）

- [ ] 全量 9,696 条打标入库（DuckDB/ClickHouse）
- [ ] 低置信（`abstention == "abstained"`）回流人工 → 季度重训
- [ ] 看板：主题 × 情感 × 时间 × 视频 × UP主；版本/舆情异常报警
- [ ] 监控**标签漂移**：新梗、新争议点（如 DLC 发布后）会长出新 L2，每月人工巡检 100 条零样本低置信样本

### 时间线

| 周 | 内容 | 产出 |
|---|---|---|
| W1 前半 | 阶段 0 + 1 | clean data + golden 600 + 规范 + κ 报告 |

### 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 反讽维度怎么都做不上去 | 高 | 降级为「不确定」三分类，低置信全部送人工；或只在长评上启用 |
| `topic_l2` 70% 达不到 | 中 | 把 ≤10 类压到 ≤6 类（合并长尾），或改用 `predict_tournament` |
| LLM 标注偏差被模型学死 | 中 | 阶段 3 的 agreement 闸门 + test 集全人工且冻结 |
| 楼中楼上下文仍不够 | 中 | 把整个楼（主楼+全部楼中楼）作为一个 state 用 `predict_long` 滑窗 |
| 新版本/DLC 后标签体系过期 | 高 | 阶段 6 的月度巡检；L2 设计成可加不可改 |
| 单纯做 sentiment+topic_l1 时被 RoBERTa 打败 | 中 | 承认它：Laya 的价值在**一次前向出 16 个异构标签**、加维度只改 JSON、概率可校准、可浏览器端跑 |
