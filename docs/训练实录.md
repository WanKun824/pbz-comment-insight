## 阶段 2：零样本基线 + 坍缩诊断 ✅（**本阶段改变了方案**）

`python run_laya.py --limit 120` 首跑即暴露坍缩：

- `valid` → **spam 35.8%**（关键词探针测得真实值 0.2%）
- `topic_l1` → **creator 72.5%**
- `sentiment` → **very_neg 49.2%**（这批数据明显偏正面：IGN 10 分、年度最佳满天飞）

### 诊断实验一：位置偏置 vs 标签文本劫持

`python diag_prompt.py`（400 条分层样本，4 个变体）

| 维度 | 变体 | collapse | entropy | flip vs A | 行/条 |
|---|---|---:|---:|---:|---:|
| topic_l1 | A 语义键·无轮转 | 0.712 | 0.508 | — | 14 |
| topic_l1 | B 语义键·满轮转 | 0.730 | 0.499 | 17.2% | 40 |
| topic_l1 | C 不透明键·满轮转 | 0.460 | 0.776 | 45.2% | 40 |
| topic_l1 | D 不透明键·无轮转 | **0.355** | **0.792** | 52.5% | 14 |

**结论：坍缩主因是模型按字面读英文语义键，不是位置偏置。**

- `option_order` 满轮转只改 13–31% 答案，collapse **毫无改善**，成本却是 **11.5 倍**（147 → 37 决策/秒）
- 换不透明键 `O1..On` 改了 42–59% 答案，collapse **0.712 → 0.355**

这正是 README 警告过的 *"choice keys are rendered verbatim and the current checkpoints can follow labels instead of the option descriptions"*。
→ **轮转关闭（`--rotate 1`），改用不透明键。**

### 诊断实验二：键命名方案

`python diag_keys.py`（同 400 条，均无轮转）

| 维度 | D 不透明键·原描述 | **E 不透明键·中文前缀** | G 中文键·中文前缀 |
|---|---|---|---|
| `valid` collapse/熵 | 0.475 / 0.822 | **0.352 / 0.962** | 0.542 / 0.825 |
| `topic_l1` | 0.355 / 0.792 | **0.320 / 0.871** | 0.320 / 0.869 |
| `target` | 0.495 / 0.730 | 0.420 / 0.798 | **0.320 / 0.870** |
| `speech_act` | 0.445 / 0.654 | **0.422 / 0.753** | 0.742 / 0.496 ❌ |

**E 方案定稿**：键 `O1..On`，描述写成 `中文类名：判定要点`。
G（中文键）在 `target` 上最好但 `speech_act` 坍缩到 74%，不稳定。

已写入 `_taxonomy/labels_v2.json` 的 `render` 段，`run_laya.render_keys()` 是唯一实现来源。

### 本阶段最重要的结论

**所有变体的 `sentiment` 都把 64–76% 判为负面**，而这批数据明显偏正面。
零样本在中文多选上不可用 —— 坐实了 README 的 *"Laya is a fast base to specialise, not a zero-shot decision engine"*。
→ **不再调 prompt，直接进入微调。**

## 阶段 3：规则弱监督 ✅

无 LLM API，所以走高精度规则 + 弃权（Snorkel 式）。
**没用零样本预测当标签**——拿一个 72% 坍缩的输出自训练只会固化错误。

`python weak_label.py` → `weak/weak_labels.parquet` + `coverage.md` + `spotcheck.csv`

### v1 → v2 的修正（来自 344 条人工抽检）

v1 抽检发现 `sentiment` 精度仅约 50–60%：

| 误例 | 弱标签 | 真实 | 根因 |
|---|---|---|---|
| 做支线对完美结局有影响吗？我好多支线任务**烂了** | very_neg | question | 「烂了」指没做完 |
| **差评**，给我狠狠漏出来啊[doge] | very_neg | banter | 玩梗反讽 |
| 奔跑映射个背键会**舒服**很多 | pos | suggest | 建议非情感 |
| 「不能用玩魂的思维打反击」 | community | combat | 「节奏」歧义 |
| 感觉那个红光就几**帧**的反应时间 | tech | combat | 「帧」歧义 |
| 黑猴后面就没做好，两年也不**更新** | creator | other_game | 「更新」歧义 |

v2 的 7 项修正：

1. 歧义词加搭配约束：`节奏`→`带节奏|舆论`；`帧`→`帧数|帧率|掉帧`；`预告`从 business 移除
2. regex bug：`十分`→`十分(?![钟秒])`；删裸的`草`；`差评`→`差评(?!率)`
3. 情感加排除门：严格疑问句 / 梗句（且 <40 字）一律弃权
4. 情感改计数制 + **双极弃权**；单极 + 转折词 → 降一档强度
5. 主题加长度门 ≥15 字，target ≥8 字
6. target 删歧义词（更新/诚意/团队/评测/老师），`other_game` 需不含指代本作的词
7. `speech_act` 严格疑问句最高优先（修 `report` 抢走提问句）

> 中间踩的坑：v2 第一版把「带转折词」直接弃权，`sentiment` 覆盖率从 23% 崩到 **2.5%**
> ——中文长评几乎必有「但/不过」。改成「双极弃权、单极降档」后回到 12.6%。

## 阶段 3b：训练集构造 ✅

`python make_train.py --cap 450`

| split | 条数 | 决策数 |
|---|---:|---:|
| train | 5002 | 9689 |
| dev | 633 | 1188 |
| test | 771 | 1485 |

三个关键处理：

1. **按 (维度, 标签) 封顶 450** —— `is_toxic` 原始 6003:11，不封顶模型只会学先验
2. **按 rpid 切分** —— 同一条评论的所有决策进同一个 split，杜绝泄漏
3. **gold schema** —— `laya.train` 要的是 `{dim: {"probabilities": {option_key: 1.0}}}`，不是裸标签（第一版因此 0 items）

同时导出 `train/golden_todo.xlsx`（589 条，分层 + 稀有类过采样，带弱标签对照列），供人工标注后**替换 test 集**。

## 阶段 4：微调 ⏳

```bash
python finetune.py --epochs 4 --micro-batch 2 --grad-accum 16 --layout parallel
```

| 配置 | 值 | 理由 |
|---|---|---|
| 基座 | `laya-multilingual` | 中文必须；English 检查点在非英语上崩（macro 0.227） |
| `option_layout` | **`parallel`** | 选项顺序无关，彻底消除位置偏置（官方：换序一致性 91.7%→**100%**，准确率持平 0.764 vs 0.779）。代价：需 transformers≥5、只能 eager 后端，ONNX/TileLang/compile 均不可用 |
| `micro_batch` × `grad_accum` | 2 × 16 = 32 | 3060 12G 的上限，实测占 11.4G |
| `gradient_checkpointing` | True | 编码器 + 决策头都开 |
| `max_len` / `head_max_len` | 640 / 320 | state P95 仅 280 字 |
| loss | `rlcd` | 严格恰当评分规则，概率可校准 |

dry_run：**9,689 valid items / 0 skipped / 1164 次优化更新**。
实测：~8 s/优化步 → 4 epochs ≈ **2.6 小时**。

训练后自动清掉继承的 `temperature_by_options`（否则旧桶值在推理时静默覆盖新拟合的 per-type 温度，官方已踩过这个坑）。

## 阶段 5：评测

```bash
python eval_model.py --ckpt ckpt/laya-pbz-v1
```

三方对照：`base`（零样本）/ `finetuned` / `majority`（多数类基线）。
每维度出 accuracy / **macro-F1** / ECE / 混淆矩阵 / 覆盖率–准确率曲线。

> **必须看 macro-F1**：`topic_l1` 里 combat 占 32%，只看 accuracy 会被多数类骗。
> **test 标签来自规则，不是人工**。它衡量「模型是否学会了规则体现的判别」，
> 不等于真实人工一致率。`golden_todo.xlsx` 标完后用同一脚本重跑才是真指标。
